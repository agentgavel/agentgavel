# AgentGavel — Top 10 AI agent frameworks worth benchmarking (checked 2026-09-03)

All star counts are live GitHub numbers fetched directly from each repo's page on 2026-09-03, not estimates.
Ranked by combined adoption signal (stars + downloads + enterprise-production evidence).

| # | Framework | Language/runtime | Adoption signal (source) | HITL/approval mechanism | Adapter feasibility |
|---|---|---|---|---|---|
| 1 | **n8n** | Node.js/TS (visual workflow engine) | 203.3k GitHub stars (github.com/n8n-io/n8n, checked live) — largest of any candidate; markets itself explicitly as "The Platform for AI Agents and Workflow Automation" | Built-in "Wait for approval" / human-input node type that pauses a workflow run mid-execution for a person to approve/edit before it continues | **Hard.** Not a code-first agent library — a visual DAG runtime with a plugin/webhook execution model. A sidecar would need to hook n8n's execution engine at the node level (custom node + webhook callbacks), not a simple event-sink import. Different integration shape than every other entry here. |
| 2 | **Dify** | Python backend, React frontend | 154.4k GitHub stars (github.com/langgenius/dify, checked live) — reached 100k+ faster than almost any AI infra project (multiple 2026 comparison sources) | LLM-app/workflow platform with approval/review steps in workflow builder; less of a programmatic hook than a UI-level gate | **Hard,** same category problem as n8n — it's an app-builder platform, not an importable agent runtime; a sidecar would sit against its API/plugin surface rather than an in-process event sink. |
| 3 | **LangChain** | Python/JS | 134k GitHub stars (LangChain's own "AI agent frameworks 2026" resource page, langchain.com/resources/ai-agent-frameworks) — still the most-searched framework name (27.1k monthly searches per SEO data) though most net-new *agent* work has moved to LangGraph | No native interrupt primitive of its own (that lives in LangGraph, which LangChain now builds agents on top of) | **Moderate.** Python, has callback/tracing hooks (LangChain callbacks), but for HITL you're really adapting LangGraph underneath it. |
| 4 | **CrewAI** | Python | 58.1k GitHub stars (github.com/crewAIInc/crewAI, checked live; multiple sources report 44-58k across the year, growing) — CrewAI's own "State of Agentic AI" 2026 survey reports 100% of surveyed enterprises planning to expand agentic AI use | `human_input=True` on a Task pauses for CLI/text input before the crew proceeds; informal/prompt-adjacent rather than a structured resumable interrupt object | **Easy-moderate.** Python, has step/task callbacks and an event bus (`crewai.events`) suitable for an event-sink sidecar; the approval hook is present but coarser than LangGraph's. |
| 5 | **LangGraph** | Python + JS (LangGraph.js) | 41.0k GitHub stars (github.com/langchain-ai/langgraph, checked live); 20+ enterprises in production per LangChain reporting (Klarna: 80% faster resolution, Uber: ~21k dev-hours saved, LinkedIn, AppFolio); ~38.8M PyPI downloads/month, ~30x AutoGen's | **Best-in-class.** Native `interrupt()` pauses the graph mid-execution, checkpoints full state, and resumes via `Command(resume=...)` — a first-class, structured, resumable approval primitive, not a bolt-on. Already an AgentGavel adapter target (v0.1, ratified-track). | **Easy** — already built (v0.1). Confirms it as the reference-quality adapter for how a real interrupt primitive should score. |
| 6 | **OpenAI Agents SDK** | Python + TS | 29.2k GitHub stars (github.com/openai/openai-agents-python, checked live; 25.6k reported early April 2026, still climbing) | Structured HITL: `needs_approval` per-tool (bool or async predicate), execution records an "approval interruption," run returns resumable state; guardrails (input/output validators) are a separate, complementary control | **Easy.** Python/TS, official SDK-level approval + guardrail hooks designed for exactly this. |
| 7 | **Google ADK (Agent Development Kit)** | Python, Go, Java | 21.4k GitHub stars (github.com/google/adk-python, checked live) — reported as the fastest-growing agent framework by stars-per-month in 2026; v2.0 hit GA June 2026 | Native since v1.14: **Tool Confirmation Flow** — `tool_context.request_confirmation()` emits a structured `RequestConfirmation` event, runner pauses until approval arrives (supersedes the older ad-hoc `LongRunningFunctionTool` pattern) | **Easy.** Purpose-built approval event type as of a 2026 release — good adapter candidate, and multi-language (Go binding exists, matching AgentGavel's Go engine). |
| 8 | **Pydantic AI** | Python | 19.7k GitHub stars (github.com/pydantic/pydantic-ai, checked live); reported fastest-growing agent framework by download volume in 2025-26 (8M+ monthly downloads by early 2026) | Native **deferred tools / human-in-the-loop tool approval** — flag a tool call as requiring approval based on args/history/user prefs, agent run pauses and is resumable; durable execution survives process restarts | **Easy.** Python, typed, approval mechanism is a first-class SDK feature, not a workaround. |
| 9 | **Microsoft Agent Framework** (successor to AutoGen) | Python + .NET | 13.3k GitHub stars (github.com/microsoft/agent-framework, checked live) — new repo, GA'd April 2026 | Structured: tools marked as requiring approval emit a pending-approval request routable to a UI/queue; graph-based `interrupt()` with checkpointing and `Command(resume=...)`, explicitly positioned as stronger than AutoGen's HITL story | **Moderate.** Python + .NET dual-runtime adds surface area vs a single-language SDK, but the approval/checkpoint model is solid and event/middleware hooks exist. |
| 10 | **AWS Strands Agents** | Python | 7.1k GitHub stars (github.com/strands-agents/sdk-python — repo now labeled `harness-sdk`, checked live) but 16.7M downloads/month (June 2026) — star count understates adoption since most usage comes through AWS product integration rather than GitHub-visible community | Hook-based: `BeforeToolCallEvent`/`BeforeToolsEvent` are interruptible, a `HookProvider` can raise `InterruptException` to pause the agent loop for any sensitive tool without modifying the tool itself; also supports async approval via Step Functions | **Easy-moderate.** Python, genuine interrupt/hook system; lower star count than others but real production HITL primitive and AWS-backed. |

## Notable also-rans (didn't make top 10, but close / worth knowing about)
- **Mastra** (~23k stars per LangChain's own comparison) — TypeScript-first, the closest thing to a "LangGraph for the JS ecosystem," worth a second look once AgentGavel needs a non-Python-adapter proof point beyond LangGraph.js.
- **LlamaIndex Workflows** — LlamaIndex core is large, but the dedicated "Workflows" (agent-orchestration) repo LangChain's own comparison cites is tiny (347 stars) — not yet a serious top-10 orchestration candidate on its own.
- **Semantic Kernel** — folded into Microsoft Agent Framework as of April 2026; no longer a separate line worth benchmarking apart from #9.

## AutoGen / CrewAI relevance verdict (explicit)

- **AutoGen: no longer top-10 relevant under that name.** Microsoft put AutoGen into **maintenance mode in October 2025** (no new features, community-only support) and shipped **Microsoft Agent Framework 1.0** as its GA successor on **April 3, 2026** — a merger of AutoGen's agent abstractions with Semantic Kernel's enterprise features (typed state, middleware, telemetry) plus graph-based workflows. The RFC's "AutoGen" adapter target should be **retargeted to Microsoft Agent Framework** (`github.com/microsoft/agent-framework`), which is also a materially better HITL story than AutoGen ever had (structured approval + checkpoint/resume vs. AutoGen's looser conversational patterns). Sources: [Microsoft Learn migration guide](https://learn.microsoft.com/en-us/agent-framework/migration-guide/from-autogen/), [AutoGen GitHub Discussion #7066](https://github.com/microsoft/autogen/discussions/7066), [AgentMarketCap coverage](https://agentmarketcap.ai/blog/2026/04/13/microsoft-autogen-maintenance-mode-agent-framework-sunset-2026).
- **CrewAI: still genuinely top-10, unambiguously.** 58.1k GitHub stars (live check), active development, and CrewAI's own 2026 "State of Agentic AI" survey shows real enterprise engagement (100% of surveyed enterprises planning to expand agentic AI use). Keep it in the v0.2 plan as-is.

## What's emerged as clearly top-tier since the RFC that isn't AutoGen/CrewAI/LangGraph/Sire
Checking the RFC file (`/Users/dndungu/Code/sirerun/gavel/docs/RFC-0001.md`) — its v0.2 scope line (§ near line 323) only names "AutoGen/CrewAI adapters," and its motivation section (line 36) name-checks LangGraph/AutoGen/CrewAI/Sire as "and others," undated more precisely than that but clearly written before this year's shakeout. Four frameworks have since become adapter-worthy on adoption + HITL-quality grounds and are **not** in the RFC's current list at all:
1. **OpenAI Agents SDK** — 29.2k stars, official first-party approval/guardrail primitives.
2. **Google ADK** — 21.4k stars, fastest-growing by star velocity, native Tool Confirmation Flow (2026).
3. **Pydantic AI** — 19.7k stars, fastest-growing by download volume, first-class deferred-tool HITL.
4. **AWS Strands Agents** — smaller star count (7.1k) but 16.7M downloads/month and a real hook-based interrupt system; include mainly because of downstream production volume, not GitHub visibility.

## Top pick for "most valuable to benchmark next" (highest adoption × lowest current adapter effort)

**LangGraph is already done (v0.1).** For the *next* adapter, the strongest adoption-to-effort ratio is **Google ADK**: it's the fastest-growing framework in the set by star velocity (21.4k and climbing faster than any other 2026 entrant per multiple sources), it just shipped a purpose-built structured approval event (`request_confirmation()` / `RequestConfirmation`, v1.14+) that maps almost directly onto AgentGavel's `ResolveApproval` contract, it's Python (straightforward sidecar), and it's Google's own official multi-language SDK (Python/Go/Java) — meaningfully different adoption base than the LangChain-family frameworks AgentGavel already covers, which makes the benchmark result more informative rather than redundant. **Pydantic AI is the close second choice** — comparable adapter ease and an even more mature deferred-tool-approval primitive, but its adoption story (download velocity, not yet matched by enterprise-production case studies the way ADK/LangGraph have) is currently thinner than ADK's.

If the criterion is pure "most enterprises actually run agents through this," **OpenAI Agents SDK** is the strongest counter-argument (first-party OpenAI backing, 29.2k stars, structured approval interruption model) and is a defensible #1 alternative pick.
